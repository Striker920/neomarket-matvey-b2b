# fix(us-b2b-06): приведены InvoiceStatusEnum и InvoiceStatus к спецификации OpenAPI

##  Цель

Реализовать endpoint создания накладной на поступление товара (`POST /api/v1/invoices`) с бизнес-валидацией статуса SKU и проверкой владельца, в соответствии со спецификацией `b2b/openapi.yaml`.

## 🔍 Контекст

Склад NeoMarket принимает товар только через накладную — это документальный след поставки. Продавец не может просто «добавить остатки» к SKU напрямую. Без накладной у склада нет основания принять партию, а у продавца нет подтверждения поставки.

## 🔧 Исправления по фидбэку арбитров

### Проблема
Использовались значения `PENDING` и `REJECTED`, которых нет в спецификации `b2b/openapi.yaml` (схема `InvoiceStatus`).

### Решение
Приведён `InvoiceStatusEnum` к значениям из спецификации:

| Было | Стало |
|------|-------|
| `PENDING` | `CREATED` (начальный статус) |
| `REJECTED` | `CANCELLED` |
| — | `PARTIALLY_ACCEPTED` (добавлено) |
| `ACCEPTED` | `ACCEPTED` (оставлено) |

## ✅ Что реализовано

### Endpoint
`POST /api/v1/invoices`

### Request body
```json
{
  "items": [
    {"sku_id": "uuid", "quantity": 10},
    {"sku_id": "uuid", "quantity": 5}
  ]
}
